# 维护已有测试

只处理本次变更涉及的测试及受影响边界，不顺便清理整个测试库。修改、删除、跳过已有测试或放宽断言，调整可能改变保护范围的快照、fixture、mock，内部重构导致旧测试失败，或新接口替代旧结构时，按以下方法判断。

## 确认保护与失败原因

先对照当前需求、公开契约及相关历史缺陷，说明旧测试保护的行为、错误路径和风险，区分行为要求与实现细节。测试存在本身不证明其期望仍然有效；实现当前输出也不能单独作为更新期望的依据。

| 判断 | 处理 |
| --- | --- |
| 当前有效行为发生回归 | 修复实现，保留对应保护；不能通过削弱断言消除失败。 |
| 已授权需求改变 | 按新契约更新期望，验证新行为及相关边界；明确废止的行为无需另建替代测试，说明对应需求决定。 |
| 行为不变，仅内部结构变化 | 核实断言是否绑定内部调用、顺序或状态，将实现耦合的断言迁移到稳定接口；必要副作用或时序本身有契约时继续保护。 |
| 测试看似重复 | 比较正常与错误路径、边界条件、运行环境和诊断价值，确认没有独特贡献后再合并或删除；同一入口不代表相同保护。 |
| 环境故障或偶发失败 | 调查环境与反馈可靠性；跳过、提高超时或增加重试不能代替原因判断。 |
| 用途或需求依据不明 | 保留并核实相关调用、需求或历史记录；缺失选择实质影响结果时再询问，不能直接判为过时。 |

## 迁移与验证

1. 将受影响的旧断言对应到仍需保护的行为、错误路径和风险，识别只描述旧实现的部分。
2. 在稳定接口建立或复用行为测试，用旧缺陷、受控扰动或来自规格、已知实例的独立预期，证明其能检测对应问题，并检查正常路径。替代覆盖要保护原风险，不能仅凭新测试通过就认定等价。
3. 替代保护得到验证后，再移除失去意义的实现耦合断言和重复覆盖。保留保护独特算法契约、协议边界、并发时序或重要诊断能力的低层测试；替身无法覆盖的真实协议和事务语义仍需契约或集成检查。
4. 调整快照、fixture 或 mock 时，检查变化是否改变了有效输入、错误路径或依赖假设；批量接受新输出不能代替逐项理解有意义的行为差异。放宽断言、提高超时或增加重试时，验证原风险仍可被检测。
5. 运行受影响的测试入口及项目要求的相关检查，核对迁移后的覆盖缺口。全绿、测试数量与覆盖率数字均不能单独证明保护有效。

## 审查与交付

实施者说明重要覆盖的保留、迁移或移除依据，以及实际验证结果和剩余盲区；无需为每条测试建立长期台账。审查者核对需求依据、原风险的覆盖去向和替代保护的证据；证据不足时说明具体风险与缺口，不把未经验证的替代报告为完成。仅审查时保持只读。

## 示例：内部发送方式变化

以下 JavaScript 为示意，并非本项目已运行的测试。`UserService` 创建用户后仍须发送两封内容正确的欢迎和通知邮件，但实现从两次 `EmailSender.send` 改为一次 `sendBatch`。旧测试绑定了内部调用次数：

```js
await userService.createUser(input);
expect(emailSender.send).toHaveBeenCalledTimes(2);
```

旧断言会因不再调用 `send` 而失败；发送两次并非契约，真正需要保护的是两封邮件及其内容。核对需求后，可将断言迁移到批量发送的内容：

```js
await userService.createUser(input);
expect(emailSender.sendBatch).toHaveBeenCalledTimes(1);
const [messages] = emailSender.sendBatch.mock.calls[0];
expect(messages).toHaveLength(2);
expect(messages).toEqual(expect.arrayContaining([
  expect.objectContaining({ to: input.email, subject: '欢迎', body: '欢迎加入' }),
  expect.objectContaining({ to: input.email, subject: '通知', body: '账户已创建' }),
]));
```

这里两项预期可区分，长度断言配合 `arrayContaining` 排除重复、遗漏或额外邮件；若预期可能重叠，还须使用精确匹配或逐项计数。也可通过端到端邮箱检查实际收到的内容。交付时说明迁移依据是发送方式属于内部细节、保留行为是两封邮件的内容；用删除或改错其中一封的受控扰动验证断言会失败，并说明 mock 未覆盖真实投递等盲区。

## 示例：需求废止自动保存

以下 JavaScript 为示意，并非本项目已运行的测试。需求明确废止编辑后五秒自动保存，改为用户点击保存按钮时保存。旧测试会因为不再自动调用保存而失败：

```js
editDocument('新内容');
advanceTimersByTime(5000);
expect(saveDocument).toHaveBeenCalledWith('新内容');
```

删除旧测试，并按新契约验证点击保存：

```js
editDocument('新内容');
clickSave();
expect(saveDocument).toHaveBeenCalledWith('新内容');
```

交付时引用废止自动保存的需求决定，并运行受影响测试验证手动保存。已明确废止的行为无需另建“不自动保存”测试，除非需求明确要求保护这一点；还应说明示例断言没有验证真实持久化等未覆盖范围。
