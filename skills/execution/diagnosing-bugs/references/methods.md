# 诊断方法选择

先说明要弄清哪个疑点、什么结果会改变判断，再选择成本合理的方法。无需备齐所有工具，也不要求每次调查都建立自动化循环。探针、环境变更及数据访问仍限于本次授权。

| 方法 | 适用条件与做法 | 证据局限 |
| --- | --- | --- |
| 差分对照 | 有已知正常版本、可信实现或可控制的环境差异时，用相同输入比较输出、状态或耗时，并逐步固定其他变量。 | 两边一致可能共享同一错误；差异也可能来自配置、协议或测量条件，不能直接证明某段实现有错。 |
| 性质测试与 fuzz | 输入空间大，且有明确不变量、有效性判断或可信对照时，在授权的隔离环境和有限预算内生成输入；保留随机种子及触发输入，再缩减为可解释的复现。 | 崩溃或违反已确认性质提供反例；没有发现失败不证明正确，覆盖和结论受输入分布及判定规则限制。缺少完整 oracle 时仍可检查已知不变量，但不能据此确认全部输出正确。 |
| 回归区间与 bisect | 已知正常与失败版本，且能在候选版本运行可区分结果的检查时，缩小变化区间；先核实环境兼容性，在隔离工作区并按项目 Git 与授权规则操作。无法判断的版本明确跳过。 | 找到的是与症状相关的变化边界，仍需解释触发机制；构建失败、环境漂移或偶发检查会误导二分，不能将其当作业务失败。 |
| 回放与边界探针 | 有请求、事件或调用链线索时，回放必要输入，或在状态转变边界观察输入、输出及时间，定位首次偏离预期的位置。 | 回放可能缺失并发、时序或外部状态；增加日志或断点也可能改变时序。不能因离线正常排除原环境问题。 |
| 人工反馈 | 视觉、交互、领域判断或用户专有环境无法由现有断言覆盖时，提供具体操作、比较材料和待判断问题，约定怎样记录结果。等待反馈时继续不依赖它的定位。 | 人的观察是带条件的证据，应保留环境、判断标准及不确定性；单次认可不能证明所有场景通过，未收到回复也不是通过。 |

找到的候选原因还要能解释原始症状。如果检查结果不稳定，或无法区分不同解释，先改进判定条件，或寻找其他证据；未经验证的解释仍标为假设。
