# 实现单项任务

交付用户指定的一项工作，使行为变化与验收证据对应。任务可以来自对话、规格或 tracker；不要求特定工具或其他 skill。

## 确定交付边界

- 读取请求、引用资料、最近的项目规则及相关实现，确认目标、非目标和可观察的完成条件。已有任务需同时读取其依赖与上层目标。
- 用现有代码核实前提。已实现的部分按实际结果验收；前提错误或条件互相冲突时说明影响。能从上下文确定的日常细节自行处理，只有实质改变结果的缺口需要澄清。
- 先查看工作区已有改动，识别需要保留的内容。共享接口、schema、迁移、依赖或跨模块状态需要扩大修改面时，先说明影响并确认仍在授权范围。

## 实现与验证

新增或调整判空、默认值、异常捕获、重试或兼容逻辑时，读取 [防御与设计原则](references/defensive-design.md)，明确失败场景及责任归属。

1. 找到产生行为的源头及项目已有抽象，选择能满足条件的最小完整改动。按项目习惯安排实现和测试；可用的专项 skill 可以辅助，但不是前置条件。
2. 修复与改动直接相关的失败。额外问题不混入当前交付；需要持续跟踪时，沿用现有记录方式。
3. 从被改包的清单、文档和检查配置确定验证范围。优先运行能覆盖行为及受影响边界的检查；通过后，仅因新失败或未解除的风险扩大检查。小而可逆、且测试只会复述实现的修改可以使用直接检查。
4. 阅读完整差异，检查范围、原有改动、错误路径及清理情况。临时探针只移除本次新增部分。

需要写入或更新任务状态时，读取 [tracker 约定](references/tracker.md)；需要保留复现、日志或交接材料时，读取 [产物约定](references/artifacts.md)。没有持久记录需求时直接在对话交付。

## 完成标准

- 每个验收条件都有通过证据，或明确列为未验证、受阻或待用户判定；后者不能被报告为已完成。
- 相关检查通过，或检查无法运行的原因与实际风险已说明；任务要求的实现未因提前汇报而中止。
- 报告行为变化、关键位置、实际验证结果和剩余项。已有 tracker 按真实状态更新。
- 提交、合并、发布、关闭外部任务按用户授权和项目规则执行；实现本身不隐含这些动作。
