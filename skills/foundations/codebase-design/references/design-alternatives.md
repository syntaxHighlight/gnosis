# 比较接口方案

当接口存在真实分歧时，按不同优化目标提出备选，例如让默认调用最简单、暴露的状态最少、协议隔离最清楚。备选须在责任归属或使用方式上有实质差别；改名不构成不同方案。

为方案使用同一组场景和限制，包括典型调用、错误处理和必要扩展。各自说明：使用者必须知道什么、实现承担什么、依赖怎样隔离、怎样验证以及如何迁移现有调用者。

比较调用成本、复杂度的封装程度、变更能否集中、失败是否容易诊断，以及迁移风险。给出推荐及理由；混合方案需要重新走过使用场景，不能只拼接各方案的优点。

可由同一代理分别推演；仅在协作规则允许且独立视角有实际价值时委派，不规定代理数量。无论如何都应先建立共同事实，避免以不同假设得出无法比较的结论。
