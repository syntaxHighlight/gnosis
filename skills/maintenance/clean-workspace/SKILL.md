# 整理工作区与提交历史

先确定用户希望整理文件、未提交修改还是已有提交历史，以及目标范围和已有授权。三个分支可以组合，但清理文件不自动提交，授权提交不自动授权改写历史，历史整理不自动推送。仅请求盘点或方案时，完成调查与具体建议；已授权执行时持续完成，不重复询问相同决定。

## 盘点与分组

读取项目规则，确认实际路径、仓库和包边界。盘点候选文件或改动的用途、来源、当前使用者、引用、归属和验证入口；涉及 Git 时同时检查分支、工作树、暂存区、相关差异及提交范围。不能只凭目录名、文件年龄、untracked 状态或提交作者判断用途和归属。

按用途或变更意图分组，区分同一文件中的不同改动，核对组间依赖。保留持续使用的记录、有效成果和未纳入授权的修改。归属或去向不明时保留对应内容，先推进不受影响的组；只有缺失决定会改变结果或确需新增权限时，给出具体选项询问。

## 按请求执行

- **清理文件与运行产物**：进入此分支前读取 [文件清理](references/file-cleanup.md) 和 [产物约定](references/artifacts.md)；涉及任务记录时读取 [tracker 约定](references/tracker.md)。用实际用途和引用证明去向，确认无用的内容才删除。
- **整理未提交修改并分组提交**：进入此分支前读取 [Git 整理](references/git-organization.md)，按意图和依赖安排提交，核对混合 hunks 与已有暂存内容。提交范围明确且已获授权时执行。
- **整理已有提交历史**：进入此分支前读取 [Git 整理](references/git-organization.md)，核实准确 base/range、共享状态、恢复入口与 dirty state 后，再按授权 squash、重排或调整提交信息。

整理中发现功能缺陷或需要重构时，说明影响并按原任务授权处理；整理本身不授权扩大业务变更。无法保持内容、归属或恢复能力时，保留现场和已完成成果，报告具体阻碍。

## 验证与完成

操作前确定每组需保留的内容和最小验证范围，操作后比较实际结果与该目标，检查保留内容、引用、最终差异和剩余状态。文件清理验证去向和引用；提交整理验证每个提交的意图、依赖与暂存内容；历史整理还要验证最终内容树及按需核验中间提交。复用仍适用的已有检查，只有出现新风险时扩大验证。

## 完成标准

报告实际完成的整理、简要依据、验证结果及仍保留或受阻的内容。涉及提交时给出提交标识和剩余工作树/暂存区状态；涉及历史改写时给出原范围、新范围和恢复入口。完成标准是已授权且证据充分的组处理完毕，保留内容未被误改，未处理项和限制明确；无需另建逐文件或逐操作报告，除非项目规范、用户或后续追溯需要。
