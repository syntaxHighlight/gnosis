# 文件与运行产物清理

只在用户请求的范围内整理和删除。清理的依据是实际用途、来源与引用，目录名、文件年龄或 Git untracked 状态都不能单独证明文件无用。

开始整理或采集清理证据前，读取 [产物约定](artifacts.md)。若涉及任务记录，再读取 [tracker 约定](tracker.md)。`.scratch` 等目录可能承载正式 tracker 或持续工作记录，按内容与项目约定判断。采集证据时同时遵循适用的捕获规则，只取判断所需的最小材料。

## 判断去向

- 盘点候选文件的用途、生成方式、引用、谁还在使用，以及能否重新生成。查看相关规则、脚本、清单和当前任务；必要时抽查内容。
- 持续使用的记录、配置、源文件和未交付结果保留。已完结但有历史或审计价值的材料按现有归档约定整理。
- 用户请求范围内、证据足以确认无用途的临时副本或运行产物可以直接删除。范围明确不意味着该范围内所有文件都可删除。
- 无法判断的文件保留，并给出具体疑问或候选处理方式；不先全部删除，再靠检查是否失败来判断用途。

## 执行与核对

删除或移动前检查真实路径与边界。对符号链接仅处理范围内的链接本身，不跟随它修改范围外目标。批量操作先核对展开后的完整目标，避免宽泛通配符匹配到其他内容。

只处理确认的目标，保留用户和其他代理的已有改动。清理不包括 Git reset、清除 stash、回滚代码、删除所有 untracked 文件，或结束归属不明的进程；这些动作需要各自明确的任务依据。

移动后检查使用这些文件的位置与链接，删除后确认目标和保留内容符合预期。只有清理影响运行入口、构建或依赖时才运行对应检查，无需为纯产物整理默认执行整个测试套件。

报告已删除、归档和保留待确认的内容及简要依据。确认已授权且证据充分的清理已完成，保留内容未被误改，范围外目标未被跟随处理。
