# 任务追踪约定

先读取项目已有说明和实际任务记录。可选配置 `.gnosis/project.json` 记录项目选择，不复制 skill 流程：

```json
{
  "version": 1,
  "tracker": { "type": "local", "path": "issues" },
  "reports": "reports"
}
```

路径相对项目根。远程 tracker 沿用项目提供的连接与状态映射；配置不授予访问或发布权限。配置缺失时可继续分析和对话交付；写入目的地有实质歧义时才询问。不要根据 Git remote 自动创建远程任务。

新建本地 tracker 使用持久目录 `issues/`。每项 Markdown 任务有 YAML frontmatter，例如：

```yaml
---
id: task-001
title: 保存用户选择
status: todo
depends_on: []
parent: null
---
```

正文保存目标、必要上下文、可观察的验收条件、验证办法及必要的进展证据，篇幅按任务决定。规格可放在已有文档位置并由任务引用，不要求复制进每张票。

`id` 是稳定且唯一的字符串；`depends_on` 是任务 ID 列表；`parent` 是可选的目标归属 ID，不能把归属关系当成前置条件。状态为 `todo`、`in-progress`、`blocked`、`done`、`cancelled`。依赖通常须 `done` 才满足；取消并不自动解除下游依赖，应重新判断要求。

读取时核对当前任务及判断所需的关联记录，不为查阅一张票审计整个 tracker。更新时检查本次变化可能影响的引用、依赖环和父子关系环，状态变化须有实际证据；必要时沿关联关系扩大检查。全量核对用于明确的 tracker 检查或整理任务。父任务还需满足自身验收条件。受阻时说明原因和解除条件，可以继续其他独立任务。不要通过删除阻塞关系或改变状态掩盖尚未完成的工作。

现有 `.scratch/<feature>/spec.md` 和 `issues/` 可能是正式 tracker。使用旧格式时遵循原配置；只有用户授权迁移才转换，预览映射并保留正文、评论、引用和状态语义。`setup-project` 若可用，提供校验与迁移工具；工具缺失时仍可人工核对小规模任务，不能伪称执行过工具验证。

任务维护不自动启动实现或授权外部关闭、提交和发布。完成记录有历史价值时可归档；有持续用途时保留，无用且经过核实才进入清理。
