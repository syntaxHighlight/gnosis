# 维护项目文档

使指定文档对目标读者准确、可用且易于查找。按请求选择事实更新、结构整理或精简，保留不属于本次范围的内容。

用户可以直接请求文档维护，实施、迁移和架构调整也可调用本技能同步受影响的说明。领域定义和架构决定由 domain-modeling 澄清，任务分类与分诊由 triage 决定，任务状态与依赖交给 maintain-tasks。根据已确认结果更新引用及说明。

目标是技能、AGENTS.md 或供代理读取的指令文档时，先读取 [指令设计](references/writing-for-agents.md)；需要改变技能流程及验证行为时使用 improve-skills。

## 核实来源

确定读者和文档用途，阅读目标文档、相关入口及引用。事实对照实现、配置和已确定的决策；历史文档保留其时间语境。文档与代码冲突时判断哪一方有充分依据，无法确定的冲突明确提出，不能默认改文档来掩盖实现缺陷。

## 修改内容

- 更新可核实的过时事实、示例和链接。步骤写明必要前提与预期结果，命令沿用项目真实入口。
- 按读者需要调整结构和术语，一处维护同一事实。合并重复内容时保留唯一的信息、限制、警告和决策理由。
- 移动或重命名前查找入链和消费者，完成后修复相关引用；历史外链或稳定路径需考虑兼容入口。
- 精简措辞不改变事实、否定、条件、不确定性或规范强度。技术示例、配置及代码块只有在本次更新确实需要且已验证时修改。
- 架构决策、术语含义和产品范围有实质变化时，确认已有决定或提出缺口；不将编辑判断写成团队已达成共识。

可用的 prose 编辑或格式专项 skill 可以辅助，缺失时直接完成上述工作。任务需要留存资料时，读取 [产物约定](references/artifacts.md)；普通编辑无需额外建立过程文档。

## 完成标准

阅读修改后的完整段落和相关入口，检查事实一致、必要信息保留及链接可达。项目有文档检查时运行相关检查；执行示例命令按其风险和授权决定，未运行的关键步骤明确说明。

交付修改位置、对读者的具体改善、验证结果和仍待确认的冲突。文档维护不隐含修改代码、任务状态或提交发布。
