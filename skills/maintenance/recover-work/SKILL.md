# 恢复工作

把当前状态核实到足以安全继续。中断通常留下可用的部分结果；验证失败并不证明这些改动可以丢弃。有交接资料时以其作为线索，没有交接资料时直接从对话、持久记录和当前现场重建，随后走相同的核实与续做流程。

## 重建上下文

1. 从可用的对话、任务记录、规格、ADR、提交记录和交接资料恢复目标、授权边界、已知决定、上次验证及下一步。阅读交接材料或需要整理恢复结果时，使用 [交接格式](references/handoff.md)，将记录中的结论与当前文件状态分开核实。
2. 查看工作区差异、相关提交、stash 和运行中的任务；识别已完成、部分完成、待验证及所有权不明的内容。如有中断任务开始前的工作区快照或差异记录，用它区分任务开始前已有的改动与该任务产生的改动。不能仅凭未提交状态判断来源。
3. 崩溃现场额外检查最近的错误、日志及未结束操作，判断是否有部分写入、锁、尚未完成的测试或后台执行者。核实进程用途、所有者和输出位置后，再选择等待、复用、修复或按授权结束；先确认操作是否已生效，再决定重试，避免重复副作用。
4. 读取关键差异及相关实现，确认结果仍符合目标。按当前风险选择能判断有效进展的检查；历史通过结果只有在输入和环境仍适用时才能复用。无法确认的目标或授权从事实中分离，继续不受影响的已授权部分，仅询问改变续做结果的缺口。

需要读取或维护持久任务时，使用 [tracker 约定](references/tracker.md)；需要整理交接、复现或运行产物时，使用 [产物约定](references/artifacts.md)。没有历史记录时从当前证据恢复，说明无法确认的部分。

## 继续推进

- 保留正确和仍有价值的部分实现，在其上修复或补全。已授权且方向明确的工作可直接继续。
- 对混合改动按可识别的修改范围处理；所有权、基线或依赖不清时保留现场，询问会影响正确性的缺口。
- 运行中的进程先确认用途与归属，再决定复用或结束。结束任务、删除文件、丢弃改动均需处于授权范围；不能用整文件还原或重置来消除不确定性。
- 任务已经完成时交付当前证据；任务仍受阻时写明具体缺口和可继续的部分，不把恢复上下文本身当作功能完成。

## 完成标准

当前目标、有效进展、剩余工作和关键不确定性已明确，且已执行当前授权下可安全继续的步骤。报告恢复了什么、实际验证了什么以及接下来受何条件限制。只有用户要求或后续执行需要时保存交接记录；可用 `handoff` 辅助生成，缺少该技能或旧交接材料时照常完成现场恢复。恢复本身不自动创建提交。
