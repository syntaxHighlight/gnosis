# 审查代码设计

检查代码复用、职责划分和错误处理，以实际行为和维护成本判断设计。

## 确定范围

沿用用户指定的范围；未指定时从当前任务或近期改动定位，仍不明确再询问。审查 diff 时固定比较基点，结合既有改动、调用者及相关规则、规格、类型、测试和设计决定阅读。

沿调用链检查实现与接口，范围外的架构问题留待后续调查。读取 [防御与设计原则](references/defensive-design.md)；模块接口或复杂度归属需要深入讨论时，可参考 codebase-design，未安装时使用包内原则。

## 重复实现

按业务规则、输入输出和调用方式查找项目中已有的能力，不能只看名称或当前 diff。对照多套实现的调用者、契约、边界行为和测试，检查规则是否分叉、修改是否需要多处同步。

说明已有实现能否复用、需要什么调整及影响哪些调用者；创建较早不代表更正确。独立领域、信任边界和支持版本可能需要不同实现，只有职责相同且有明确收益时才建议统一。用途或调用情况不明的列为待核实项。

## 防御与抽象

先判断防御是否必要，再确定责任位置，最后检查保留的处理是否正确。追踪输入和已有保证，核实防御在支持的调用路径上何时触发。

检查重复判空、掩盖错误的默认值或异常捕获、无恢复需求的重试，以及为假想调用者准备的兼容分支。考虑能否删除、合并、直接传播错误，或在源头修正契约与无效状态。说明这些调整如何改善行为或减少维护负担，不能只凭写法、行数或模式名称判断。

需要保留的处理，检查正常、失败和恢复时的结果，包括重试边界与重复副作用。删除可能改变公开行为时，核对依赖它的调用者和测试；新增处理须指出现有机制未覆盖的失败路径。

## 独立复核

审查自己刚写的代码、争议设计或重要结论时，若支持且允许协作，建议使用不继承对话历史的子代理。提供范围、比较基点、项目规则、需求来源、文件入口和已确认约束，暂不提供自己的结论或预期发现。

子代理只读审查，返回位置、触发条件、后果、依据和未知项。主代理核实证据与分歧，不以意见一致代替判断。空白上下文只能减少先入为主，不能保证无偏见。不固定代理数量；无法协作时自行按同样标准审查。

## 验证与交付

阅读代码或运行已有且无外部副作用的最小检查。验证若需要额外权限、写入或生产故障注入，报告证据缺口，不执行这些操作。

按影响排列已确认的问题，说明位置、触发场景、契约依据、后果，以及建议调整后的行为和验证办法。待核实项单列；需要解释取舍时，说明应保留的独立实现或防御。范围内疑点均已核实或列明证据缺口后，交代覆盖范围、验证方式和未验证项；没有确认的问题就如实说明。

默认在对话中报告。用户要求文件时，按 [产物约定](references/artifacts.md) 保存到指定位置或项目报告目录；可用 present-report 辅助呈现。只交付报告，不修改被审项目、配置或任务记录，不创建或发布 spec、ticket。后续工作由用户决定。
