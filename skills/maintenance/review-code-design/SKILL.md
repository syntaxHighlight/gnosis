# 审查代码设计

检查指定范围的代码复用、职责划分和错误处理，以实际行为和维护成本判断设计，主动寻找能明显简化结构的改法。

## 确定范围

沿用用户指定的范围；未指定时从当前任务或近期改动定位，仍不明确再询问。审查 diff 时固定比较基点，结合既有改动、调用者及相关规则、规格、类型、测试和设计决定阅读。

沿调用链检查实现与接口，范围外的架构问题作为后续调查入口。本技能交付范围内可证实的问题及改进提案；跨模块重划、多个改造方向或完整迁移比较交给 `improve-codebase-architecture` 深化。复用已有架构调查与审查证据，仅补查变化和缺口。

读取 [防御与设计原则](references/defensive-design.md)；涉及模块接口、复杂度归属、方案比较和测试迁移时，若 `codebase-design` 可用，读取其 SKILL.md 并使用其方法；未安装时结合真实调用说明责任、收益、代价和验证办法。

## 重复实现

按业务规则、输入输出和调用方式查找项目中已有的能力，不能只看名称或当前 diff。对照多套实现的调用者、契约、边界行为和测试，检查规则是否分叉、修改是否需要多处同步。

说明已有实现能否复用、需要什么调整及影响哪些调用者；创建较早不代表更正确。独立领域、信任边界和支持版本可能需要不同实现，只有职责相同且有明确收益时才建议统一。用途或调用情况不明的列为待核实项。

## 防御与抽象

先判断防御是否必要，再确定责任位置，最后检查保留的处理是否正确。追踪输入和已有保证，核实防御在支持的调用路径上何时触发。

检查重复判空、掩盖错误的默认值或异常捕获、无恢复需求的重试，以及为假想调用者准备的兼容分支。考虑能否删除、合并、直接传播错误，或在源头修正契约与无效状态。说明这些调整如何改善行为或减少维护负担，不能只凭写法、行数或模式名称判断。

需要保留的处理，检查正常、失败和恢复时的结果，包括重试边界与重复副作用。删除可能改变公开行为时，核对依赖它的调用者和测试；新增处理须指出现有机制未覆盖的失败路径。

## 独立复核

主代理默认将独立复核交给未参与实现、且不继承当前对话历史的审查代理。提供范围、比较基点、项目规则、需求来源、文件入口、验证证据和已确认约束，让审查者独立形成判断。

审查者只读检查，返回位置、触发条件、后果、依据和未知项。主代理核实证据与分歧，按必要视角安排复核，不固定代理数量。运行环境或协作规则无法支持独立审查时，自行按同样标准检查，并明确独立性的限制。

## 结构性简化提案

对确认有维护或运行负担的部分，主动比较更大幅度的改法。

- 删除整层包装、历史兼容分支或无实际收益的中转接口。
- 合并承担相同规则的实现，把责任移回拥有数据和不变量的模块。
- 使用项目已有能力或成熟实现替换私有实现，说明契约、依赖与迁移影响。
- 通过类型、构造方式或状态转换消除无效状态，减少散落的校验和恢复分支。
- 改变算法、数据布局或调用链，减少运行成本及阅读时必须同时理解的状态与层次。

逐项说明要保留的行为、预期收益、影响范围、代价和验证办法。将尚待测量的性能收益及尚未验证的替代设计标为假设。改进提案可以超出局部修补幅度，提出后仍需通过调用与约束判断是否值得实施。

## 验证与交付

阅读代码或运行已有且无外部副作用的最小检查。检查产生的缓存和临时输出按产物约定处理。验证若需要额外权限、修改被审文件或生产故障注入，报告证据缺口，不执行这些操作。

按影响排列已确认的问题，说明位置、触发场景、契约依据和证据、后果，以及建议调整后的行为和验证办法。确认问题须有可追溯的真实调用、历史缺陷或性能测量直接支持；纯粹依据结构经验的判断只作为待核实改进提案。

另列值得验证的改进提案与待核实项，避免把结构偏好报告为已确认缺陷。共同背景只交代一次，检查项不逐项回显；解释应保留的独立实现或防御。没有确认问题也可交付有依据的改进提案。

范围内疑点已核实或列明证据缺口，重要结构简化方向已评估，且覆盖范围与验证限制明确时，审查完成。

默认在对话中报告。用户要求文件时，按 [产物约定](references/artifacts.md) 保存到项目 `reports/` 目录；可用 present-report 辅助呈现。只交付报告，不修改被审项目、配置或任务记录，不创建或发布 spec、ticket。后续工作由用户决定。
