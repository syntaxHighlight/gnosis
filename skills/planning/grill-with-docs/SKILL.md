# 访谈与领域记录

通过追问厘清方案，只把未来读者仍会用到的知识写入项目文档。访谈本身不是规格生成或实现任务。

可用时以 `grilling` 主持访谈、以 `domain-modeling` 辅助记录；没有这些技能时按本文完成。

阅读相关实现、现有术语表和决定记录，区分当前事实、目标行为和假设。按决定的依赖逐轮询问：提供可行选项、建议和代价，用具体场景检验答案；等待影响后续问题的回答。对话节奏由关键分歧和用户偏好决定。

在用户授权的文档范围内维护以下内容；沿用项目既有位置和格式，确有内容才创建文件：

- 领域术语：持续出现在需求、代码或协作中的概念。记清含义、边界及容易混淆的概念；短期工作名和实现细节留在对话中。
- 设计决定：只有决定具有长期影响、未来读者需要知道理由，且确实比较过有代价的替代方案时才形成 ADR。写明背景、选择、理由、后果和状态。临时排期、显而易见的选择不形成 ADR。

不把试探中的说法写成已确定的事实。术语冲突先展示不同含义；尚未作出的决定保留未决状态。已有 ADR 被新决定替代时保留历史并建立关联，不覆写当时的理由。

收束时汇总关键结论、未决项和实际修改的文档。完成标准是重要分歧已处理且有持续价值的记录准确反映结论；没有值得长期保存的内容时，纯对话也是完成。此技能不授予范围外写入、提交、推送或发布权限。
