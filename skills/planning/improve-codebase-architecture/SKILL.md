# 寻找值得做的架构改进

从实际修改成本、运行成本和阅读负担出发，寻找值得投入的结构改进。优先按用户指定的位置或任务选择调查入口；否则用近期变更、缺陷或调用热点选择。没有这些信号时，从被最多模块引用的模块或最长的入口到叶子调用链入手；这只是默认选择，不是优先处理的证据；交付时说明缺少哪些信号及实际采用的兜底入口。读取相关术语和设计记录，列出约束与评价标准。

本技能负责发现整体改造方向、比较备选及迁移路径。`review-code-design` 负责核实指定代码范围中的设计问题和简化提案。已有审查结论可作为调查输入，沿其证据深化；已有架构调查也可供专项审查引用，避免重复扫描整个代码库。

## 独立调查

默认由未参与相关实现、且不继承当前对话历史的新上下文代理调查。提供范围、代码入口、领域约定、已有 ADR、约束和需要回答的问题，让代理独立发现候选。主代理继续核实事实和调用边界，收到结果后检查关键证据、合并重复候选并处理分歧。代理数量依据可独立调查的范围决定。

运行环境或协作规则无法支持独立调查时，说明限制，按同一范围自行调查。已有有效的独立调查结果可以复用，并核对代码和约束是否仍适用。

可用时参考 `codebase-design`；独立使用时以以下标准判断：接口包含调用者必须理解的参数、顺序、错误和约束；好的模块把复杂行为封装在易用接口后，让相关变化集中。少文件、少行数或多一层抽象本身不是改善证据。

沿真实调用路径寻找重复规则、泄漏的状态、难以通过行为验证的耦合和跨模块改动。对每个候选核实代码位置、受影响调用者与实际后果。设想去掉现有抽象：复杂度会消失、转移还是散落回调用方？据此判断该合并、重划接口还是保留结构。

主动检查幅度较大的改法，包括删除整层、合并职责、替换私有实现、改变算法或数据布局、重新划分模块边界。对有价值的候选，同时比较保留现状、局部改进和结构性改造，选择存在实质差异的方案展开。方案幅度由收益和约束决定，允许提出需要迁移的新方向。已有 ADR 可以因新证据重新讨论，说明原理由与当前条件的变化。

为各方案使用同一场景和限制，比较调用方式、复杂度归属、性能或阅读成本、迁移代价、验证办法及可逆性。测量结果与收益假设分别标明；关键收益无法仅凭阅读确认时，提出 `prototype` 实验的问题、对照与成功条件。

## 展示可比较的候选

先简列有证据的候选及优先判断，数量由证据决定，不凑数量；没有值得做的改进也可明确报告。只对值得优先处理或进一步核实的候选展开，说明涉及的位置、已观察到的修改障碍、改进方向、收益、迁移及验证风险、证据强度。共同背景只交代一次，不为每个候选重复。

重要结构方案默认提供前后关系图，并用文字说明调用者需要知道什么、复杂行为从哪里移到哪里。前后图使用相同场景、命名和粒度，清楚标注拟议结构及未验证假设；少量且关系简单的发现可以直接用表格表达。

制作候选图示时，读取 [候选呈现示例](references/candidate-example.md)，用同一场景比较前后责任与验证接口，避免只展示文件数量变化。

复杂调查默认制作可打开的 HTML 报告；若 `present-report` 可用，制作前读取其 SKILL.md 并使用其方法，未安装时自行按以下层次组织报告。少量发现直接在对话中用表格交付。制作文件前读 [产物约定](references/artifacts.md)，放入项目根固定的 `reports/`，不通过配置覆盖；已有其他位置的报告不自动移动，接入迁移先预览并确认。首屏给推荐、主要收益和待决定问题，随后用同一组维度比较方案；优先候选展示前后图，代码证据、迁移步骤和次要候选按需展开。共同背景集中说明，详细程度服务于选择下一步。

可使用 CDN，但说明在线资源依赖；关键结论和比较在脚本不可用时仍可读。检查默认视图、图例、链接、窄屏阅读和主要展开操作，避免图过大、文字过密或依靠颜色表达状态。

给出优先建议与理由，交由用户选择深入方向。若候选违背现有决定，明确新证据为何足以重新讨论。用户选择后，可用 `grill-me` 追问关键权衡；没有该技能时自行讨论约束、接口、依赖与验证策略。接口尚未达成共识时保持为候选。

完成标准是重要候选具有可追溯证据、实质备选及验证路径，前后变化和取舍可理解，用户能够选择下一步。没有值得做的改进时交付调查范围与依据。后续实施、领域决定记录和发布遵循对应任务范围。
