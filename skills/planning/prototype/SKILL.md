# 原型与设计实验

先把问题写成可判定的假设，确定哪种观察会支持、推翻或仍不足以回答它。读取相关约束、典型调用和现有方案，使用同一场景比较候选。接口与职责取舍可使用 `codebase-design`，架构调查可将未验证的候选收益交给本技能。

## 选择实验形式

| 分支 | 默认实验及完成依据 |
| --- | --- |
| 交互设计 | 制作有实质差异的候选，使用相同数据和任务，提供直接切换及关键状态；通过实际操作比较信息层次、操作路径与反馈 |
| 状态与逻辑 | 制作可操作的小模型或可运行场景，展示输入、动作、状态转换和结果；覆盖争议场景、边界和失败恢复 |
| 性能与技术比较 | 建立基线、代表性输入和控制变量，以相同条件运行候选；记录时间、吞吐、资源或其他相关指标，说明重复次数、波动及环境 |

按问题选择一个主分支，需要时组合。无法判断形式且选择会改变产物时再澄清，其余从材料确定并说明关键假设。候选应在机制、布局或职责上不同，改名或换色不足以验证结构性取舍。

## 制作与运行

1. 先读取 [产物约定](references/artifacts.md)，选择项目内明确标识的实验位置或隔离工作目录，将自己创建的文件、进程与数据记录为对话列表或 `README.experiment.md`，供收尾核对。使用测试数据或明确的实验存储，核实运行命令及依赖范围。
2. 实现足以暴露问题的最小可运行程序。交互和逻辑问题优先简单启动入口，必要时用单个 HTML。性能问题使用适合真实运行路径的工具，排除明显的预热、缓存、I/O 和计时方法偏差。
3. 实际运行代表性场景，保留关键结果与可重跑入口。模型化实验需说明与真实系统的差异；模拟数据和本地测量只支持相应范围的结论。
4. 对照假设比较方案，主动检查反例。结果不支持原建议时修正判断；证据不足时给出最小的后续实验。涉及用户可见的交互差异时，保留用户对方案的选择权，分别说明测量结论与体验偏好。

实验阶段优先速度和可观察性，检查必须足以支持结论。需要持久化、外部资源、依赖变动或生产数据时先确认已有授权与隔离方式；原型行为进入正式实现前，再按项目规范处理完整错误路径、兼容性和长期测试。

## 结论与收尾

交付问题、基线与候选、实际观察、推荐及局限，提供启动方式或结果入口。性能提升区分实测值与预期，说明适用负载和可能代价。已有规格、工单或 ADR 需要更新时，在授权范围记录验证结果并引用实验来源。

保留仍用于决策、复现或交接的实验及必要证据并说明用途，清理本次已无用途的临时文件、数据和进程；对照清单确认相应文件和进程已不存在。保存实验分支或提交依照项目交付方式和授权执行。问题已得到有范围的答案，或剩余不确定性与下一次验证明确时，实验完成。
