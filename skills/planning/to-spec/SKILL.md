# 综合规格

把已有共识整理为实现者可使用的行为契约。此技能确定“做什么、怎样算完成”；任务切片由 `to-tickets` 等后续工作承担。

读取用户提供的材料及相关项目上下文，沿用领域术语和有效的设计决定。核实影响规格的当前行为；标明事实来源、已确认决定、合理假设与开放问题。材料中的建议不自动成为用户决定。

规格的结构随问题规模调整，以下是内容核对点，不要求逐项设章；相关内容可以合并，没有实际内容的栏目无需填写：

- 用户问题、目标和使用者，以及会改变验收的场景。
- 对外可观察行为、必要的错误或边界行为、兼容性约束。
- 明确的验收条件，以及消除范围歧义所需的非目标。
- 已作出的关键技术决定，以及验证行为所用的接口、现有测试依据和重要盲区。

涉及多角色或多条用户流程时，用用户故事说明谁需要什么、为什么需要；需要跨条目追踪时给故事编号，让相关行为和验收条件引用编号，两者可以是多对多关系。小修或纯技术变更可以直接说明问题、预期行为和验收，无需套用角色句式或另建故事列表。对照输入检查是否遗漏范围内的角色、主要流程和关键异常，每项要求是否有来源和对应验收；使用故事时检查故事是否有对应行为与验收。材料未明确的角色或收益应标为假设。

例如，输入已确认支持收藏与取消收藏，可以写成“US-1：作为读者，我希望收藏文章，以便稍后找到”。“收藏后可在收藏列表找到文章”和“取消收藏后从列表移除”两个验收点都可引用 US-1。

优先选择能覆盖本次主要风险、层次尽可能高且稳定的现有测试接口，说明验证入口、覆盖范围和影响验收的重要盲区；选择存在实质取舍时再解释理由。高层接口无法暴露的风险，可以补充低层验证；需要新接口时解释其成本，常规选择无需额外审批。只在位置或代码片段本身属于契约、或比文字更精确时纳入；避免把临时实现猜测固定成要求。

直接综合已有材料，不为排版细节或常规实现选择重启访谈。缺失信息实质改变范围或验收时，明确列出阻塞点并提出集中问题；其余部分继续整理。带有阻塞项的规格应标为草案，不能宣称已可实施。

用户要求保存或发布时，先读 [跟踪约定](references/tracker.md)，沿用现有项目目的地；配置缺失不妨碍在对话中交付。外部发布遵循已有授权，不因调用本技能获得额外权限。

完成时交付规格正文或实际链接，说明未决项及就绪状态。规格可被独立读懂、验收条件可检查且没有将推断冒充共识时，综合工作完成。
