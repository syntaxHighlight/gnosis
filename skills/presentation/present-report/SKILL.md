# 呈现报告

围绕读者要理解或决定的问题组织已有证据。报告可以是 Markdown、HTML 或用户指定格式；格式服务于用途，不为装饰增加图表或交互。

创建或更新文件前，读取 [产物约定](references/artifacts.md)。报告放在工作区 `reports/`，同主题优先更新既有报告，保留必要的来源与时间语境；项目已有约定优先。

## 组织证据

确认报告对象、读者和所需决定，核对输入资料的来源、日期、单位和比较口径。事实、推断、建议及未知项清楚区分；证据不足时说明缺口，不为了完整页面补造结论。结论靠近支撑它的证据，详细日志通过路径或链接提供。

先给主要发现及其影响，再按问题关系展开。比较适合表格，关系适合图，变化适合曲线；内容简短时直接使用文字。不规定图表数量，也不要求每份报告都有图。

复杂方案比较、架构调查或证据量较大的交付，读取 [比较报告布局](references/comparison-layout.md)。多方案、多层证据且需要切换或筛选时默认采用 HTML；少量结论使用 Markdown 表格。已有报告格式满足阅读需要时沿用。先让读者看懂决定，再按需展开调查深度。

## 制作与验证

- 交互只用于读者需要筛选、比较或探索的部分，默认状态即能呈现主要结论。控件含义、单位和状态清楚，键盘可用，图表不只靠颜色传达差异。
- 数据、图例和正文保持同一口径，标注缺失值与不确定性。引用能追溯到材料，链接指向具体支撑内容。
- HTML 报告优先采用可直接打开的本地资源。需要 CDN 时可以使用，但应在交付中说明联网依赖和离线受影响的功能；重要结论保留可读的文字或表格。
- 按格式检查渲染、链接、溢出和交互，验证代表性数据与主要操作。只在报告代码或依赖变化确有风险时增加相应检查。

## 完成标准

读者能从报告中找到结论、证据、限制及必要行动。交付报告路径、验证结果和真实的使用限制。生成报告不隐含外部上传、网站发布或向他人发送。
