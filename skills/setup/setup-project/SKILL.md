先检查项目现有 `AGENTS.md` / `CLAUDE.md`、工单说明、术语与 ADR、`issues/`、`.scratch/` 和 `.gnosis/project.json`。用户请求项目接入时，提出迁移到统一 Gnosis 约定的方案；用户只请求校验或局部配置时按其范围处理。迁移确认前继续尊重现有规则，普通分析可先于 setup 开始。

## 接入步骤

1. 盘点任务系统、分类与分诊语义、文档位置、验证入口和 Git 交付约定。读取实际记录与命令，标明未知项。盘点时按项目已有记录读取，无需立即运行工具；仅当需要校验配置格式、预览迁移结果或应用迁移时，才按下文准备 Node.js 20+ 和 npm 依赖环境。
2. 给出目标约定和迁移差异。Gnosis 项目产物固定为本地任务 `issues/`、术语表 `GLOSSARY.md`、ADR `docs/adr/`、规格 `specs/` 和报告 `reports/`，不通过配置覆盖。已有远程 tracker 可以继续使用。涉及 ADR 约定时，读取 [ADR 维护约定](references/decision-records.md)。只创建本次需要的文件和目录。
3. 将需要用户决定的迁移、已有改动处理和交付偏好集中呈现。已确认的选择直接复用，配置说明与操作授权分别记录。发现非标准旧路径配置时说明其不能继续覆盖固定位置，核对实际文件及引用；不因更新配置自动移动现存文件。
4. 在确认范围内迁移并建立发现入口。tracker 使用下面的预览与应用流程；术语表、ADR 和其他文档按路径、标识、状态与入链映射进行人工迁移，现有 CLI 只处理 tracker。验证目标内容和引用后切换权威入口，源记录的归档或删除按已确认方案执行。
5. 核对配置与真实入口一致，报告已完成接入、实际验证及待人工处理项。

迁移、切换 tracker 与新建配置是不同操作。现存项目文件继续按原入口读取，接入迁移须先预览并确认；未迁移的记录不冒充已完成接入。

## 配置与校验

配置示例、字段说明与状态语义详见 [跟踪约定](references/tracker.md)。完整接入时写入 `.gnosis/project.json` 作为统一发现入口，保留与本次接入无关的扩展字段；旧项目和单项分析可以暂时缺少配置。

### 配置与记录校验

按下文“本地工具的运行环境”准备环境后，**在本技能目录执行** `node scripts/tracker.mjs config <项目根绝对路径>` 校验配置。本地记录采用 Gnosis schema 或已迁移到该格式时，再执行 `node scripts/tracker.mjs check <项目根绝对路径>`，检查唯一 ID、字段格式、依赖与 parent 引用、依赖环与父子归属环（分别检查），并校验配置。没有配置时也扫描项目根的 `issues/`；远程配置通过不代表远程记录已验证。

请求是否缺信息、适合代理执行或需要人工判断由 triage 判断；`to-spec` 负责拆分，`maintain-tasks` 负责创建、合并、更新任务记录与维护状态；本工具只验证 YAML 和配置约束。勾选 tickets/spec 的完成项或设为 `done` 之前，逐项核对可观察验收条件和证据；结构校验通过不代表功能完成。

沿用 Matt Pocock、旧版 frontmatter tracker 或其他既有格式时，使用其原生检查方式；没有工具就核对相应格式的状态和引用。不能把新检查器不支持的字段当成旧记录错误，也不能为通过检查隐式迁移。迁移中的未知值需澄清后映射。

## 迁移与完成

迁移时先读 [references/migration.md](references/migration.md)，运行不带 `--apply` 的预览，检查路径、状态、ID 和引用映射，处理所有错误。向用户展示具体源、目标、状态转换及未解决项，获得迁移的明确确认后，才运行同一命令加 `--apply`。预览失败不允许写入；复杂引用可明确停止自动迁移，不能宣称全面支持。

完成条件是本次需要的配置可发现，项目入口与固定产物约定一致，涉及的记录按实际格式完成核对。迁移还需新格式检查通过并验证目标与引用，之后按用户已确认的 tracker 选择更新配置；报告修改位置、验证结果与仍需人工处理的事项。既有 `AGENTS.md` / `CLAUDE.md` 只在需要补充发现入口或修正迁移后失效规则时局部修改。

## 本地工具的运行环境

只有需要运行检查或迁移工具时，才由代理准备环境。确认 Node.js 20+ 和 npm 可用；在本技能目录检查本地 `yaml` 依赖是否已按锁文件安装。已就绪则直接使用，缺失或版本不匹配时，由代理在该目录运行 `npm ci --ignore-scripts`，再用 `node scripts/tracker.mjs --help` 确认工具可运行。不要在用户项目中添加该依赖，也不要每次调用都重新安装。

准备过程遵循当前环境的写入和联网权限。缺少 Node.js、目录不可写或安装失败时，说明具体阻碍；不要自行安装系统运行时，也不能将未执行的检查报告为通过。普通配置和文档工作可以继续。
